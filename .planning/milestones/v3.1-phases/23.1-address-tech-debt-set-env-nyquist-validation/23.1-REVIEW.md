## Warnings

### WR-01: Conflict test contains unreachable `steps_completed` assertion (D-07)

**File:** `src/mcp/tools/setup.test.ts:562-564`  
**Issue:** After `expect(isSetupErrorResult(result)).toBe(true)` (line 553), the guard `if (!isSetupErrorResult(result) && 'steps_completed' in result.data)` is always false, so the `not.toContain('env')` assertion never runs. Plan 05 intended D-07 coverage here; the dead branch gives false confidence.

**Fix:** Remove the impossible guard. Error responses do not carry `steps_completed`; D-07 is already guaranteed by code order (`push('env')` only after successful sync). Either delete lines 562–564 or add an integration test that exercises real `handleApplicationEnvsSync` conflict detection (mirror `application.test.ts` D-08) and asserts setup error code without manifest/env completion side effects.

## Info

### IN-01: No test coverage for `env_file` delegation path

**File:** `src/mcp/tools/setup.test.ts:385-630`  
**Issue:** All successful delegation tests use `env_content`. The `env_file` branch at `setup.ts:769` is untested in setup tests (path handling lives in `application.ts`, but setup wiring is not asserted).

**Fix:** Add one test with `set_env: true, env_file: '<tmpdir>/.env'` asserting `handleApplicationAction` receives `env_file` and not `env_content`, plus `not.toHaveProperty('conflict_policy')`.

### IN-02: `deploy_and_watch` silently skips non-application resources (asymmetry with `set_env`)

**File:** `src/mcp/tools/setup.ts:757-763`, `782`  
**Issue:** `set_env` throws when `resource.type !== 'application'`. `deploy_and_watch` only runs inside `resource.type === 'application'` with no validation error, so greenfield `create-one-click` + `deploy_and_watch: true` completes successfully with `deploy_watch` left in `steps_remaining`. Not a regression in this phase, but agents may assume deploy ran.

**Fix:** Optional — mirror the `set_env` guard and throw `COOLIFY_VALIDATION_ERROR` when `deploy_and_watch: true` on a non-application resource.
