## Spacing Scale

Mapped to **text density & structure** in tool descriptions, error envelopes, and README tables. Declared multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px equiv. | Inline gaps — space after `·` in catalogs; comma in param lists |
| sm | 8px equiv. | Blank line between tool purpose sentence and `Actions:` catalog |
| md | 16px equiv. | Blank line between catalog block and `Safety:` footer |
| lg | 24px equiv. | Blank line between README recipe intro and action table |
| xl | 32px equiv. | Section break before README code examples (` ```js ` block) |
| 2xl | 48px equiv. | Blank line before README cross-ref to `service.list-types` |
| 3xl | 64px equiv. | Reserved — out of scope |

**Structural rules:**

| Rule | Value |
|------|-------|
| Catalog separator | single middle-dot ` · ` (U+00B7) with one space each side |
| Catalog max visual width | ≤120 characters per logical line; wrap continuing with `· ` |
| Params per action in catalog | 1–4 key params; optional suffix `?` |
| `recoveryHints` array | 2–4 strings per error; each ≤160 characters; imperative next step last |
| README action table | exactly 3 rows for recipe actions; 1:1 EN/DE column parity |
| Safety footer | exactly one line after catalog |

Exceptions: none.

## Typography

Roles map to **text hierarchy** in MCP descriptions and README (not CSS). Four sizes, two weights:

| Role | Size | Weight | Line Height | Maps to |
|------|------|--------|-------------|---------|
| Body | 16px | 400 | 1.5 | Tool purpose sentences; README recipe intro; `recoveryHints` prose |
| Label | 14px | 400 | 1.4 | Safety footer; `Note:` soft guidance; README Safety paragraph |
| Heading | 20px | 600 | 1.2 | README `### 🍳 recipe` section title (markdown H3) |
| Display | 28px | 600 | 1.2 | Unused — reserved token; do not emit in Phase 20 strings |

**Mono emphasis:** present bare identifiers — `create-git-app`, `service.list-types`, `DATABASE_URL`, `gitea`, `COOLIFY_RECIPE_PARTIAL_FAILURE` — never paraphrased.

**Weights used:** 400 (body/label), 600 (heading only).

### Tool description anatomy

#### `recipe` tool (`src/mcp/tools/recipe.ts` → `server.ts`)

```
Multi-resource orchestration recipes & dynamic provisioning.
Actions: create-git-app(server_uuid, git_repository, git_branch, repo_path?, build_pack?) · create-app-db(server_uuid, app_name, db_name, db_engine, env_key?) · create-one-click(server_uuid, type, instant_deploy?)
Safety: optional instance · reveal opt-in only
```

| Element | Locked copy |
|---------|-------------|
| Purpose | `Multi-resource orchestration recipes & dynamic provisioning.` |
| Catalog | `recipeActionsCatalog` constant (exact string above) |
| Safety footer | `Safety: optional instance · reveal opt-in only` |
| Confirm gate | **Absent** — recipe creates intentional (D-17) |
| Dry-run | **Absent** — no preview action (D-18) |

#### `service` tool — `list-types` action (catalog entry)

| Element | Copy |
|---------|------|
| Catalog token | `list-types(format?, projection?)` — must appear in `serviceActionsCatalog` after `get(...)` |
| Purpose (implicit) | Discover one-click service type IDs from live `service-templates.json` — no local YAML catalog |
| Success shape | `{ id: string, label: string }[]` stable-sorted by `id` ascending (`localeCompare`) |
| Label fallback | When template `name` missing, `label` = `id` |

### `MANIFEST_HINT` (D-20 — canonical string)

```
Tip: pass `instance` to target a registered Coolify instance or use the manifest tool to record context (D-20 soft manifest hint).
```

**Required on error `recoveryHints` for:**

| Path | Status |
|------|--------|
| `create-one-click` unknown `type` | ✅ shipped |
| `create-app-db` env-wiring `COOLIFY_RECIPE_PARTIAL_FAILURE` | ✅ shipped |
| `create-git-app` Zod validation errors (`throwValidationError`) | ⚠ gap — must append `MANIFEST_HINT` (20-VERIFICATION D-20) |
| `create-git-app` runtime `COOLIFY_VALIDATION_ERROR` (e.g. missing `build_pack`) | ⚠ gap — must append `MANIFEST_HINT` |
| `create-git-app` `CoolifyApiError` from API failures | ⚠ gap — must append `MANIFEST_HINT` |

### Empty states

| Surface | Heading | Body |
|---------|---------|------|
| `list-types` zero templates (empty `{}` from CDN) | Templates unavailable | Treated as fetch failure — `COOLIFY_FETCH_TEMPLATES_FAILED`; not a silent empty array |
| `list-types` success with types | — | Populated `{ id, label }[]`; agent picks `type` for `create-one-click` |
| `create-one-click` before list-types | Unknown type risk | Error message directs: `Call service.list-types for valid IDs` |
| `create-git-app` no `repo_path` and no `build_pack` | Missing build pack | `build_pack is required when repo_path is omitted` + recoveryHints incl. `MANIFEST_HINT` |

### Error states

| Code | When | Message pattern | recoveryHints (minimum) |
|------|------|-----------------|-------------------------|
| `COOLIFY_FETCH_TEMPLATES_FAILED` | CDN + GitHub Raw both fail, or empty `{}` | `Could not fetch service templates from CDN or GitHub Raw.` | `RECOVERY_HINTS.COOLIFY_FETCH_TEMPLATES_FAILED` (outbound internet; GitHub access) |
| `COOLIFY_VALIDATION_ERROR` | Zod / business validation | Field-specific joined messages | Base `RECOVERY_HINTS.COOLIFY_VALIDATION_ERROR` + action-specific bullets + **`MANIFEST_HINT` on all recipe error paths** |
| `COOLIFY_RECIPE_PARTIAL_FAILURE` | App+DB partial create | `Database created successfully but application creation failed: …` OR `Application and database created but env wiring failed: …` | No-auto-delete guidance + created UUIDs in `error.data` + **`MANIFEST_HINT` on env-wiring path** |
| Unknown one-click `type` | `type` not in catalog | `Unknown one-click type '{type}'. Call service.list-types for valid IDs.` | list-types call · catalog key rule · **`MANIFEST_HINT`** |
| `build_pack=dockercompose` on create-git-app | D-12 reject | `build_pack='dockercompose' is not supported on create-git-app — use service.create or create-one-click` | Standard validation hints + **`MANIFEST_HINT`** |

**Error envelope shape (agent-consumed):**

```json
{
  "ok": false,
  "error": {
    "code": "COOLIFY_VALIDATION_ERROR",
    "message": "…",
    "recoveryHints": ["…", "MANIFEST_HINT"],
    "data": { "application_uuid": "…", "database_uuid": "…" }
  }
}
```

`data` present only when partial resources exist (D-15).

### Success envelope shape

```json
{
  "ok": true,
  "data": { "application_uuid": "…", "build_pack": "dockerfile", "deploy": { "status": "queued" } },
  "_meta": { }
}
```

| Action | Success `data` fields |
|--------|----------------------|
| `list-types` | `[{ id, label }, …]` |
| `create-git-app` | `application_uuid`, `build_pack`, `deploy.status` |
| `create-app-db` | `application_uuid`, `database_uuid`, `connection_string` (masked), `env_key`, `deploy.status` |
| `create-one-click` | `service_uuid`, `type` |

`connection_string` masked unless `reveal: true` (D-19).

### Destructive confirmation

| Action class | Confirmation |
|--------------|--------------|
| Recipe creates (`create-*`) | **No confirm gate** — intentional create (D-17) |
| Partial failure cleanup | **No auto-rollback** — explicit copy: "Do not delete the database; it is fully functional." |
| Resource delete (out of scope) | Unchanged — existing confirm gates on domain tools |

## Interaction Contract (MCP / agent)

| Interaction | Contract |
|-------------|----------|
| Discovery flow | `service.list-types` → pick `id` → `recipe.create-one-click` with `type: id` |
| Git flow | Pass `repo_path` for auto `build_pack` OR explicit `build_pack`; remote URL via `git_repository` |
| App+DB flow | Single `create-app-db` call; sequential DB → app → env wire; partial failure returns UUIDs |
| Template fetch | Version-pinned CDN → GitHub Raw fallback; hard fail on double failure (D-03) |
| Instance routing | Optional `instance?` on all recipe + list-types calls; soft manifest hints in errors (D-20) |
| Schema shape | Flat Zod per Phase 19; `createFlatActionSchema` with three recipe actions |
| Validation | Strict — extras rejected; wrong action fields → `COOLIFY_VALIDATION_ERROR` |
| Animation | N/A |
